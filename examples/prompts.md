# Example requests

All names and records in the accompanying demo are fictional. These prompts work on your own interface without needing the sample app.

## Build a work queue

> Use $compact-admin-ui to create a support queue with search, status filters, assignee, priority, and a clear record-detail action. Use fictional content. Keep the first records visible in the first viewport and include a narrow-screen layout.

## Refine an existing table

> Use $compact-admin-ui to tighten this order-list page. Inspect effective gaps and repeated card padding first. Preserve the existing components, columns, permissions, and business behavior. Keep all essential labels readable and verify keyboard focus and narrow-screen overflow.

## Build record details

> Use $compact-admin-ui for a fictional service-request detail page. Group related metadata, make the current status and next action clear, and separate activity history from current fields. Do not create a new card around every attribute.

## 中文：优化留白

> 用 $compact-admin-ui 优化这个后台页面的密度。先检查父子容器的 gap、margin、padding 和固定高度是否叠加；保留当前组件库、品牌、功能和数据，减少无效留白，不要靠缩小文字把内容塞进去。

## 中文：列表与状态

> 用 $compact-admin-ui 做一个虚构的订单列表，包含搜索、状态筛选、金额、负责人和详情操作。表格内数字对齐，状态不能只靠颜色表达，同时提供初始加载、无搜索结果和提交失败时的处理方式。

## Keep a broader workflow

> Continue the design workflow already in use, and use compact-admin-ui as the style brief for this work surface. Keep the existing design system authoritative and inspect the actual rendered result.
